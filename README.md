## Сценарий

1. Клиент открывает меню демо-кафе и выбирает блюдо.
2. Клиент оформляет заказ и получает его идентификатор. Начальный статус заказа — `pending`.
3. Отдельный сервис кафе получает новый заказ через API и подтверждает его.
4. Клиент запрашивает заказ по идентификатору и видит статус `accepted`.

## Объём работы

В проекте два сервиса: основное API и сервис демо-кафе. Основное API отдаёт меню, создаёт и хранит заказы, возвращает их статус. Сервис кафе получает новые заказы и подтверждает их через основное API.

Для демонстрации используется одно кафе с заранее заполненным меню. Подключение других заведений и редактирование меню через API остаются за рамками КТ2. Сценарий проверяется запросами к API.

## Планируемый стек

- Python и FastAPI — API сервисов.
- SQLite — хранение меню и заказов.
- Docker Compose — совместный запуск сервисов.

## План проверки

- Получить меню, создать заказ, подтвердить его через сервис кафе и проверить статус `accepted`.
- Проверить, что API отклоняет пустой заказ, неизвестное блюдо и количество `0`.
